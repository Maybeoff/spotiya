# PlayPlay-декодер

Spotiya использует обычный аудиоключ Spotify первым. При явном отказе AP
она может обратиться к PlayPlay и передать поток отдельному `playplay-decoder`.
Этот экспериментальный декодер запускает ограниченный набор x86_64-функций
через Unicorn, в том числе на ARMv7. На Мини 2 проверены звук, чтение и перемотка;
поддержка всех треков и аккаунтов не проверялась.

## Установка готового дополнения

В Spotiya 0.9.3 и новее откройте `spotiya addons`, выберите **PlayPlay** и нажмите
Enter. Команда для терминала: `spotiya addon install playplay`. Пакет берётся из
GitHub Releases той же версии. После проверки SHA-256 архива, отдельных файлов,
архитектуры и протокола он устанавливается в
`/data/opt/spotify-connect/playplay/bin/playplay-decoder`. APK для установки не нужен.
Работающий приёмник подхватывает его без перезапуска; при ошибке загрузки трека
повторите воспроизведение после установки.

Готовый пакет содержит C-обвязку, статический Unicorn и выделенные фрагменты
кода и таблиц Spotify Android 9.1.92.3058. Полный APK, данные аккаунта и ключи
пользователя не включены. Происхождение и лицензии записаны в `sources.json`,
`revisions.json` и `licenses/` внутри дополнения. Основной пакет Spotiya
декодера не содержит. Ниже описана самостоятельная сборка из соответствующего APK.

## Входной файл

Нужен Spotify Android **9.1.92.3058**, содержащий
`lib/x86_64/liborbit-jni-spotify.so` размером **27 955 696 байт** с SHA-256:

```
c0d5f6a1ccadb6ada0faf32f270c293ff412f5ddc02a3918ab09486970b10a38
```

Скрипт принимает целый APK или уже извлечённую библиотеку. APK только с ARM
библиотеками не подходит. Другие сборки отклоняются до извлечения ресурсов:
адреса функций и данные зависят от точной версии библиотеки.

## Сборка на Linux x86_64

Нужны Python 3 с venv, Git, CMake, Ninja и GCC. Для ARMv7 используется тот же
Linaro toolchain, что и для Spotiya. Из корня репозитория:

```sh
python3 -m venv .cache/decoder-venv
.cache/decoder-venv/bin/pip install -r decoder/requirements.txt
scripts/bootstrap-arm.sh
DECODER_PYTHON="$PWD/.cache/decoder-venv/bin/python" \
  scripts/build-playplay.sh /путь/к/Spotify.apk armv7
```

Результат — `dist/playplay-decoder-armv7`. На проверенной сборке ARMv7 размер
составляет 1 097 148 байт; результат может меняться с инструментами сборки.
Вариант для проверки на ПК: заменить `armv7` на `host`.

Unicorn 2.1.4 загружается из закреплённого коммита
`8028ec436f2d9376525352dd38ed9ed6b9f6be10`. Его исходники, сборка и сгенерированный
`resources.h` хранятся в `~/.cache/spotiya/`. Переопределения:
`SPOTIYA_CACHE`, `SPOTIYA_TOOLCHAIN`, `DECODER_UNICORN`, `DECODER_PYTHON`,
`SPOTIYA_JOBS`. Входной APK не копируется в репозиторий.

Для одной проверки извлечения без компиляции:

```sh
.cache/decoder-venv/bin/python decoder/prepare.py \
  /путь/к/Spotify.apk .cache/decoder-resources/resources.h
```

Генератор проверяет SHA-256 исходной библиотеки, применяет статические относительные
релокации ELF и проверяет SHA-256 выделенных страниц. Данные процесса телефона
и учётной записи не используются.

## Размер и память

Сборка скрывает внутренние символы статически подключённого Unicorn: отдельный
декодер общается через stdin/stdout и не экспортирует API для других процессов.
Образ из 161 страницы отображается 23 непрерывными областями вместо 161 отдельных.
После копирования образа в Unicorn исходные полные файловые страницы освобождаются
через `MADV_DONTNEED`; при повторной установке ключа они читаются из файла заново.
Буфер JIT ограничен 1 МиБ.

В сравнении на Мини 2 с одинаковыми входами размер файла снизился
с 1 129 500 до 1 097 148 байт (примерно 2,9%). После расшифровки 1 МиБ данных
RSS одного процесса снизился с 6544 до 4736 КиБ, PSS — с 5680 до 3945 КиБ.
Дополнительная проверка с двумя сохранёнными ответами PlayPlay и повторной
установкой ключа показала RSS до 4892 КиБ. Сравнение выполнялось отдельными
процессами без воспроизведения; основной приёмник не включён в эти цифры.
Расшифровка и чтение по произвольным смещениям совпали с AES-эталоном.

## Работа на колонке

Декодер запускается только после явного отказа обычного аудиоключа;
при успешном AES, сетевой ошибке или таймауте он не запускается.
`playplay/bin/playplay-decoder --info` показывает размер ресурсов и версию протокола;
команда не подключается к сети. Декодер не получает токены аккаунта и работает
через stdin/stdout с родительским процессом. Процесс завершается при освобождении
трека или ошибке. В TUI дополнение показывается как `Ready (on demand)`.

Старое ручное расположение `playplay-decoder` рядом с `spotiya` поддерживается;
при наличии обоих файлов используется дополнение из `playplay/bin/`.
Для удаления остановите Spotiya, удалите каталог `playplay` (и старый
`playplay-decoder`, если он есть) и запустите приёмник снова.

На Мини 1 этот путь пока не проверялся.

## Исходники и лицензии

C-обвязка и генератор распространяются под [MIT](../LICENSE).
Отдельный исполняемый файл статически использует
[Unicorn](https://github.com/unicorn-engine/unicorn/tree/8028ec436f2d9376525352dd38ed9ed6b9f6be10)
с его GPL-2.0 и уведомлениями зависимостей; он не линкуется в основной бинарник
Spotiya. Выделенные фрагменты Spotify APK не покрываются MIT-лицензией Spotiya.

## Пакет для GitHub Releases

Actions не извлекает APK: `python3 decoder/package.py` скачивает закреплённый
готовый ARMv7-пакет из более раннего релиза, проверяет SHA-256 архива и бинарника
по `decoder/prebuilt.json`, затем создаёт манифест для текущей версии Spotiya.
Контрольные суммы исходников движка также сверяются с закреплённой сборкой:
при изменении C-кода, генератора, раскладки или скрипта сборки CI требует
пересобрать декодер и обновить закреплённый пакет.

Для публикации новой нативной сборки после `scripts/build-playplay.sh`:

```sh
python3 decoder/package.py --binary dist/playplay-decoder-armv7 \
  --unicorn-source ~/.cache/spotiya/unicorn-2.1.4
```

Результаты: `dist/spotiya-playplay-armv7.tar.gz` и `dist/PLAYPLAY_SHA256SUMS`.
Архив включает уведомления Unicorn, сведения об исходной библиотеке, хеши
исходников движка и бинарника. После публикации новой сборки обновите URL и
контрольные суммы в `decoder/prebuilt.json`.
